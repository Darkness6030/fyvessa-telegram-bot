# Аудит требований

Проверено по `specifications.xmind` и `finances.xmind` 09.08.2026. Прямые уточнения имеют приоритет над исходными картами: email полностью исключён, web-админки нет, каталог редактируется через Excel, административные операции выполняются ботом.

Статусы: **готово** — сценарий реализован; **частично** — есть основа, но не весь пользовательский путь; **не сделано** — рабочего сценария пока нет.

## Пользовательская часть

| Пункт ТЗ | Статус | Что есть / чего не хватает |
|---|---|---|
| 1. Telegram-бот | Частично | Точка входа, меню, операционная `/admin`, уведомления о наличии и статусах заказа готовы. Реальные реквизиты оплаты ещё не подключены. |
| 2. Приветствие | Готово | `/start` создаёт пользователя и выводит приветствие со всеми четырьмя inline-кнопками. |
| 3. Mini App | Частично | Есть каталог, поиск, карточки, избранное, недавние, корзина, профиль, заказы, коины и промокоды. Встроенная поддержка ещё не готова; отзывы по уточнению вынесены в отдельный канал. |
| 5. Каталог | Готово | Товары, поиск, категории, фильтр цены, популярные, новинки и рекомендации выводятся. |
| 6. Категории | Частично | Категории динамически создаются из Excel и выводятся в каталоге. Отдельные изображение, скрытие и удаление категории через Excel пока не предусмотрены. |
| 7. Товар | Готово | Создание и изменение основных данных, фото, цен, скидки и категории выполняются через `assets/products.xlsx`; пропавший SKU скрывается. |
| 8. Скидка товара | Готово | Старая и новая цены берутся из Excel, выводятся в каталоге и применяются к заказу. |
| 9. Карточка товара | Частично | Фото, данные, цены, категория, корзина, избранное и рабочий запрос наличия есть. Не хватает отзывов товара. |
| 10. Популярные | Частично | Есть ручной признак из Excel и счётчики просмотров/корзины. Автоматическое ранжирование по метрикам и покупкам не подключено. |
| 11. Новинки | Готово | Метка действует семь дней с даты создания товара. |
| 12. Недавно просмотренные | Готово | Просмотр записывается автоматически, последние товары выводятся отдельным списком. |
| 13. Избранное | Готово | Добавление, удаление, просмотр списка и переход в карточку работают. |
| 14. Узнать наличие | Готово | Пользователь отправляет количество из карточки; администратор отвечает кнопкой или командой с количеством и комментарием, пользователь получает уведомление. |
| 15. Корзина | Готово | Добавление, удаление, изменение количества, товарная скидка, выбор персональной скидки/промокода, коины, итог и checkout работают. |
| 16. Подтверждение количества | Готово | Корзина запрашивает конкретное количество в едином админском чате, автоматически обновляет ответ и блокирует checkout без достаточного подтверждения. |
| 17. Регистрация | Готово | `User` создаётся по Telegram-сессии, редактирует имя, фамилию, дату рождения и `phone_number`; неполный профиль блокирует первый заказ. Email намеренно исключён. |
| 18. ID пользователя | Готово | `User.id` сразу равен Telegram ID; отдельного внутреннего ID и дублирующего `user_id` нет. |
| 19. Карточка пользователя | Частично | `/user <username/id>` показывает данные, регистрацию, баланс, скидку, заказы и запросы с кнопками. Пригласивший хранится в `User.referrer_id`. |
| 20. Профиль | Частично | Личные поля, Telegram/internal ID, коины, скидка и переход к заказам работают. Рефералы и поддержка пока не выведены. |
| 21. Мои заказы | Готово | Список, состав, снимки цен, скидки, коины, сумма и статусы доступны в профиле. |
| 22. Коины | Частично | Баланс, применение после скидки, журнал списания и возврат при отмене работают; начисления за активности ещё не реализованы. |
| 23–24. Скидка и рефералы | Частично | Скидка и простая связь `User.referrer_id → User.id` есть; `/start <Telegram ID>` сохраняет пригласившего. Проверка подписки и начисления ещё не реализованы. |
| 25–26. Промокод и выбор скидки | Готово | Корзина и заказ взаимоисключающе применяют персональную скидку или активный промокод, затем коины. |
| 27–28. Промокоды и партнёры | Частично | Admin flow создаёт, изменяет и включает/отключает промокоды. Полной карточки статистики и выплат партнёра ещё нет. |
| 29. Оформление и оплата | Готово для ручного перевода | Заказ показывает `PAYMENT_DETAILS`; сообщение об оплате и кнопки проверки приходят в единый админский чат. Платёжный провайдер не используется. |
| 30. Учёт промокода после оплаты | Готово | Партнёрское вознаграждение фиксируется только при первом подтверждении оплаты администратором. |
| Отзывы | Готово по уточнению | Ссылка на Telegram-канал `REVIEWS_CHANNEL_URL` присутствует только в приветствии бота; web-страниц и хранения отзывов нет. |
| Поддержка | Частично | Бот ведёт по внешней Telegram-ссылке; встроенных обращений и истории нет. |

## Финансы

| Блок ТЗ | Статус | Что есть / чего не хватает |
|---|---|---|
| Расчёт продажи и варианты скидок | Готово | Checkout применяет товарную скидку, персональную скидку либо промокод, затем коины. |
| Доли Дианы и Булата | Готово | При идемпотентном подтверждении оплаты рассчитываются и сохраняются прибыль и обе доли по снимкам владельца/процента. |
| Карточка оплаченной продажи | Готово | `Order`/`OrderItem` сохраняют номер, пользователя, цены, скидки, коины, опт, прибыль, доли, статус и время оплаты. |
| Отчёты по периодам, товарам и людям | Не сделано | В боте есть только общая числовая сводка. Финансовые отчёты и Excel-экспорт отсутствуют. |
| Начисления и выплаты | Частично | Начисления фиксируются в оплаченном заказе; отдельный учёт истории выплат пока не добавлен. |
| Неизменяемая история | Готово | Строки заказа получают снимки SKU, названия, категории, цен, владельца и процента; финансы фиксируются при первой подтверждённой оплате. |

## Что можно проверить сейчас

- запуск контейнера зависимостей `rewire`, применение Alembic-схемы и синхронизацию `assets/products.xlsx`;
- публичный Jinja2-каталог, поиск, фильтры, главную страницу и карточку товара;
- отклонение персональных API без Telegram `initData` и работу с корректно подписанным `initData` без cookie;
- создание `User` с Telegram ID в `id`, первоначальное заполнение имён и сохранение изменённых имён, даты рождения и `phone_number`;
- избранное, недавно просмотренные, корзину и профиль через персональные API;
- Telegram-команды и inline-кнопки при наличии реального токена и публичного HTTPS URL.

Нельзя проверить как готовые пользовательские сценарии пункты со статусом «не сделано». Production-проверка также требует PostgreSQL, реального Telegram-бота и HTTPS Mini App URL.
