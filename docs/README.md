# Fyvessa Telegram Bot + Mini App

Один Python-проект для Telegram-бота и пользовательского Mini App. Web-интерфейс рендерится Jinja2 и стилизуется Tailwind CSS; отдельного frontend-проекта и web-админки нет.

## Локальный запуск

```bash
cp .env.example .env
docker compose up --build
```

Compose поднимает приложение на `http://localhost:8080` и PostgreSQL 16 во внутренней сети. Данные БД сохраняются в именованном volume `postgres_data`. Для полноценного запуска нужен настоящий `TELEGRAM_TOKEN`. `MINI_APP_URL` обязан быть настоящим публичным HTTPS-адресом этого приложения: `example.com` и открытие localhost в обычном браузере не дают Telegram `initData`. Frontend сохраняет `Telegram.WebApp.initData` на время Mini App и передаёт его в `X-Telegram-Init-Data` и совместимом `Authorization` при каждом запросе.

Для запуска Python вне контейнера сначала поднимите `database`, опубликуйте его порт либо укажите доступный PostgreSQL в `DATABASE_URL`. SQLite больше не используется.

## Каталог

Источник данных — Google-таблица `Fyvessa Admin` с четырьмя листами:

- `products` — товары; поля `is_active`, `is_popular`, `is_recommended` отображаются галочками, а `category` и `owner` выбираются из выпадающих списков;
- `categories` — название, изображение и галочка активности категории;
- `owners` — имя, процент доли и галочка активности владельца;
- `settings` — реквизиты оплаты и ссылки на основной канал, отзывы и поддержку.

На листе `settings` используются строки `channel_url`, `reviews_channel_url`, `support_url` и `payment_details`. Для поддержки можно указать полную ссылку, `t.me/...`, `@username` или username без `@`.

Доступ выполняется через service account из локального `assets/credentials.json`; таблицу нужно предоставить адресу `client_email` из этого файла с правами редактора. Файл credentials игнорируется Git и Docker build context; в Compose он попадает в контейнер через bind mount `./assets:/app/assets`.

`sku` нельзя менять после публикации товара: по нему синхронизация находит существующую запись. Категории и владельцы управляются на своих листах; отсутствующая категория из строки товара автоматически добавляется в справочник. Товары, удалённые из полной таблицы, скрываются, а не удаляются из БД. Форматируемые ошибки исправляются и записываются обратно в Google Sheets; строка с невосстановимой критической ценой или названием деактивируется до проверки администратором.

Администратор после изменения таблицы запускает в боте `/sync_products`. При старте приложения каталог и настройки также загружаются автоматически. Некорректные ссылки очищаются; кнопка без ссылки не показывается.

## Рабочие сценарии

- профиль требует имя, фамилию, дату рождения и телефон перед первым заказом;
- избранное, история просмотров и корзина работают через подписанный Telegram `initData`;
- в корзине меняются количество, персональная скидка/промокод и коины;
- «Узнать наличие» сразу отправляет запрос с кнопками в единый админский чат;
- checkout доступен только после подтверждения нужного количества каждого товара; корзина автоматически обновляет ответы;
- заказ показывает реквизиты из листа `settings`, а кнопка «Я оплатил» отправляет проверку платежа в админский чат;
- подтверждение оплаты администратором идемпотентно фиксирует прибыль, доли и партнёрское вознаграждение.
- кнопка «Отзывы» есть только в приветственном сообщении и открывает ссылку из листа `settings`; моделей и модерации отзывов в приложении нет.
- реферальный параметр — обычный Telegram ID: `/start <id>` записывает его в `User.referrer_id`; отдельного кода и отдельной таблицы связей нет.

Оплата выполняется ручным переводом по реквизитам из Google Sheets, после чего администратор подтверждает платёж в Telegram.

## Команды администратора

`/admin` открывает меню очередей, сводки, пользователей, промокодов и синхронизации. Все действия работают только в чате `ADMIN_CHAT_ID`.

```text
/user <username/Telegram ID>
/discount <username/ID> <0–100>
/availability <ID> <available|unavailable|on_request> [количество] [комментарий]
/order <ID> <paid|cancel>
/promo CODE | Партнёр | скидка | вознаграждение
/promo_toggle CODE
/sync_products
```

Карточка `/user` содержит кнопки заказов, запросов наличия и обновления данных.

## Структура

- `src/main_flow.py` — только пользовательские Telegram-сценарии;
- `src/admin_flow.py` — все административные Telegram-сценарии;
- `src/routes.py` — пользовательские Mini App routes;
- `src/catalog.py` — контракт каталога и транзакционная синхронизация с БД;
- `src/sheets.py` — загрузка, автокоррекция и оформление Google Sheets;
- `src/settings.py` — типизированные настройки магазина и их загрузка при старте;
- `src/orders.py` — создание заказа и идемпотентные переходы оплаты/отмены;
- `src/models.py` — модели `rewire_sqlmodel`;
- `Dockerfile`, `docker-compose.yml` — приложение и PostgreSQL 16;
- `templates/`, `static/` — Jinja2 + Tailwind пользовательский интерфейс;
- `docs/GOAL.md`, `docs/RULES.md`, `docs/PLAN.md` — цель, ограничения и этапы проекта;
- `docs/TZ_AUDIT.md` — сверка текущей реализации с каждым блоком исходного ТЗ.
