# Fyvessa Telegram Bot + Mini App

Единое Python-приложение магазина: Telegram-бот служит точкой входа и административным интерфейсом, а FastAPI/Jinja2 Mini App предоставляет каталог, профиль, корзину и заказы. Отдельных frontend- и web-admin-проектов нет.

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

Приложение доступно на `http://localhost:8888`, PostgreSQL 16 работает во внутренней сети Compose. Для Telegram Mini App нужны настоящий `TELEGRAM_TOKEN` и публичный HTTPS `MINI_APP_URL`; обычный браузер и localhost не предоставляют подписанный Telegram `initData`.

Обязательные переменные окружения перечислены в `.env.example`. Service account Google хранится в `assets/credentials.json`, не коммитится и попадает в контейнер через bind mount `./assets:/app/assets`. Таблица `Fyvessa Admin` должна быть доступна `client_email` из credentials с правами редактора.

## Google Sheets

В таблице используются:

- `Владельцы` — русские колонки `Владелец` и `Доля`;
- `Настройки` — русские колонки `Ключ`, `Значение`, `Описание`; значения ключей: `channel_url`, `reviews_channel_url`, `support_url`, `payment_details`;
- остальные листы — категории товаров; название листа и есть название категории.

Отдельных листов `products` и `categories` нет. Товарные листы используют колонки:

```text
image_url | sku | name | description | characteristics |
retail_price | wholesale_price | discount_price |
is_active | is_popular | is_new | owner
```

`is_popular` и `is_new` — чекбоксы. Только они управляют попаданием товара в блоки «Популярное» и «Новинки» внутри своей категории; дата создания и статистика на эти блоки не влияют. На главной эти блоки представлены вертикальными автоматически прокручиваемыми лентами.

В колонке A находятся встроенные изображения Google Sheets, а не URL. При синхронизации приложение экспортирует таблицу в XLSX, извлекает оригинальные байты в `assets/catalog`, создаёт локальный манифест и раздаёт файлы по `/catalog/images/<file>`. При временной ошибке Google используется только полностью пригодный предыдущий кэш.

`sku` является стабильным идентификатором и после публикации не меняется. Пропавшие из таблицы товары и категории скрываются в БД, а не удаляются. Восстановимые форматы нормализуются и записываются обратно; критически некорректная строка товара деактивируется. Технические строки характеристик (`наценка`, `доставка`, `поставщик`, себестоимость и подобные) отбрасываются.

Каталог и настройки синхронизируются при старте. После ручных изменений администратор может выполнить `/sync_products`.

## Основные сценарии

- персональные HTTP-запросы проверяют Telegram `initData` без cookie и собственных web-сессий;
- при оформлении сохраняются данные получателя, телефон, служба доставки (СДЭК, Почта России или Ozon) и адрес пункта выдачи;
- работают поиск, фильтры, избранное, история просмотров и корзина;
- наличие конкретного количества подтверждает администратор;
- товарная скидка применяется первой, затем персональная скидка или промокод, затем коины;
- реквизиты берутся из `Настройки`, оплату вручную подтверждает администратор;
- финансовые и доставочные данные заказа сохраняются снимками и не меняются после редактирования каталога;
- в Mini App доступна история заказов и отправлений со статусами «Оформлен», «Собирается», «Отправлен» и «Доставлен»;
- тема Mini App переключается между светлой и тёмной и сохраняется на устройстве; приветствие и кнопка «СТАРТ» находятся в боте;
- отзывы не хранятся: кнопка в приветствии открывает внешний Telegram-канал.

## Команды администратора

Все команды доступны только в `ADMIN_CHAT_ID`.

```text
/admin
/user <username/Telegram ID>
/discount <username/ID> <0–100>
/availability <ID> <available|unavailable|on_request> [количество] [комментарий]
/order <ID> <paid|cancel|assembling|shipped|delivered>
/promo CODE | Партнёр | скидка | вознаграждение
/promo_toggle CODE
/sync_products
```

## Структура

- `src/catalog.py` — контракты каталога и транзакционная синхронизация БД;
- `src/sheets.py` — чтение и нормализация товарных листов и владельцев;
- `src/settings.py` — модель, кэш и синхронизация листа настроек;
- `src/sheet_utils.py` — схемы колонок и общие операции Google Sheets;
- `src/sheet_images.py` — экспорт XLSX, OOXML-разбор и кэш изображений;
- `src/models.py`, `src/orders.py`, `src/pricing.py` — данные и бизнес-логика;
- `src/main_flow.py`, `src/admin_flow.py` — пользовательский и административный Telegram flow;
- `src/routes.py` — страницы и API Mini App;
- `templates/`, `static/` — серверный интерфейс;
- `scripts/migrate_catalog_sheets.py` — разовая миграция исходных таблиц в текущий формат.

`GOAL.md` фиксирует границы продукта, `RULES.md` — инварианты, `PLAN.md` — оставшиеся работы, `TZ_AUDIT.md` — фактическое покрытие требований.
